# この仕様書の構造 — なぜ普通の仕様書と違うのか

**この機能は 2 回、実装が紙面と違うものになって作り直しになった。**

| 回 | 何が起きたか |
|---|---|
| 1 回目 | 受領本文をそのまま流した。画面 20,297 字 / 受領 20,490 字 = **削減率 1%**。全リバート |
| 2 回目 | ダイジェストを作ったが、**モックと照合しないまま本番へ**。検査値の並びがモックと違っていた |

**2 回とも直接の原因は同じ: 仕様書の散文を読んで実装し、モックを見なかった。**

そこで本書は **紙面のことを一切書かない。**

> ## 【最重要】紙面の正はモックであり、この仕様書ではない
>
> - どのカードが / どの見出しで / どの文を / どの順で 出るか — **すべてモックが持つ**
> - **本書にそれを書き写さない。** 書き写すと「もう一つの正」ができ、実装者がどちらかを選ぶ。**それが 2 回の失敗の正体**
> - 本書が定義するのは **正の所在・素材・変更手順・検証・未裁定** の 5 つだけ

##### `blood_test.json` に混ざっている問診 24 件は表から外す【発注者指示 2026-09-01】

**Elith が混ぜたのではない。** デメカルの血液検査 CSV が問診結果を持ち
（`elith-blood-csv.ts` の `項目区分` = 1:検査値 / **2:問診結果** / 3:判定）、
**当社の上りがそれを納品している**。ただし当社は列ごとの凡例でコードを
**ラベル（`ハイ`/`イイエ`）に変換して**渡すのに対し、受領 JSON は**生のコード（0/1/2）**で
凡例が無い。設問ごとに極性が違う（`1→ハイ 2→イイエ` / `0→イイエ 1→ハイ`）ため、
**Elith 側は推測するしかなく実際に取り違えている** — 「肉料理…= 2」を「好む」、
「タバコを吸っている = 2」を「吸っていない」と**同じ 2 を逆に**読んでいる。

**切り分けの規則（暫定）**: Elith の JSON に `項目区分` が無いので**キーの形**で分ける。
**設問文 = ひらがな 2 文字以上 ／ 全角括弧 ／ 読点 のいずれかを含む。**

- **実測（2026-09-01）**: タイプ1 の 3 ファイル ＋ タイプ2 の `health_checkup` の
  **計 121 キーで誤判定 0**（検査値 18/18 を残し、問診 24/24 を外した）
- **採らなかった案**: 文字数で切る（「夜食や間食が多い」は 8 字で破綻）／
  標準マスタ照合（starter 41 項目では**アルブミン・中性脂肪・血清鉄など本物の検査値が 17 件落ちる**）／
  本文が名指しした項目だけ採る（**HDL-C・LDL-C・TC など 8 件が落ちる** — 本文は「HDLコレステロール」と書くため）
- **外した件数は監査に出す**（黙って落とさない）
- **恒久策は Elith に `項目区分` かラベルを残してもらうこと**（§6.4 の確認事項に追加）

##### `health_age` が `null` の回は当社の元の値で埋める【発注者指示 2026-09-01】

ウェルネス年齢は**当社が CABA で算出して `HealthAgeData` として Elith へ渡した値**で
Elith は計算しない。したがって Elith が返さなかったときに**当社の元の値で埋めるのは、
新しい数字を作ることではない**。どちらを出したかは監査に残す（紙面には出さない）。

> **併せて直したバグ**: `Number(null)` は 0 で `Number.isFinite` を通るため、
> `health_age: null` の検体で**紙面に「ウェルネス年齢 0」が出て、冒頭の数直線も
> 0 歳の位置に点を打っていた**（目盛りが 0〜80 に伸びる）。値が無いことと 0 歳は別。

##### 基準値の抽出は区切り文字に依存させない【実装済み 2026-09-01】

3 世代で **`基準値：` → `基準値:` → `基準値 `（コロン無し）** と変わっており、
今回は **1 件も拾えず検査値表が 8 行 → 0 行**になっていた（§9.3.1 と同じ失敗の 2 回目）。
**構造 `名前は 値（基準値 …）` は 3 世代とも不変**なので、そこだけに依存する形にした。
実測: タイプ2 は 8 件で**現行と完全一致**（回帰なし）、タイプ1 は 0 → **7 件**。

**あわせて「黙って空にしない」**（§5.3）— 本文の節はあるのに 1 件も拾えないときは
受領形式が変わった合図として監査に出す。

## 4.1 紙面の文言は Elith の出力 JSON にあるものだけ【確定・発注者裁定 D-C3】

> **Elith の出力 JSON に無い文言・表現は使わない。**

見本 PDF にある語も、Elith 出力に無ければ使わない（「要注意項目」「良好な項目」など）。
**見本からは枠だけを借りる**（§4.3）。

### 逐語ルールの例外【2026-09-18 に全面改訂・発注者指示】

> **診断報告書に、Elith の受領 JSON に無い文言を足してはならない。**

**旧版の「構造ラベル（カード見出し・表の列見出し）は例外」という抜け穴を閉じた。**
この抜け穴のせいで、**受領 JSON に存在しない「基準値」「判定」という列**と、
空欄の **「—」**、受領 JSON に **0 件**の **「今回の所見」** というカード見出しが
紙面に出ていた（§4.14）。

| 出してよいもの | 条件 |
|---|---|
| **受領 JSON の逐語** | 12 字以上の文字列が受領 JSON の部分文字列であること。**短い語の部分文字列一致は認めない**（短い語は何にでも当たり、照合として意味を持たない） |
| **Elith の見出しマーカー** | `【現状評価】` `### 4. 1か月の食事改善プラン` のように **Elith が本文に見出しとして書いた語** |
| **器・操作の語** | 「全編」「詳しい説明を読む」「PDF にして保存する」等。`verify:report-verbatim` の `ALLOW` に**理由つきで**列挙する |
| **表紙の台帳** | 作成日 / 紙面の版 / 検査日 / 第 N 回 / 実年齢。**当社が持っている事実**の名前 |

**足してはならないもの（`ALLOW` に載せても通らない）**

- **診断の中身を名乗る語** — 判定 / 所見 / 基準値 / 要注意 / すぐ受診
- **空欄のプレースホルダ** — `—` `N/A` 等。**「欄はあるが該当なし」に見せることになる**。
  値が無いなら**欄ごと作らない**
- **当社の散文** — 空状態の説明文、但し書き、注記

**例外の登録は `scripts/verify-report-verbatim.mjs` の `ALLOW` が唯一の場所。**
散文でここに書き足しても効かない（機械が見るのは `ALLOW` だけ）。

## 4.3 紙面デザインの正 = Wellfort 提示のフォーマット見本【確定・発注者指示 2026-08-29】

**`docs/elith/フォーマット見本_AI疾病予防レポート.pdf`（A4 18 ページ・画像のみ）を踏襲・トレースする。**

| | |
|---|---|
| **踏襲するもの** | **デザインと様式のみ** — 色・レイアウト・見出しの型・表の型・余白・フッター |
| **踏襲しないもの** | **項目と内容。** 見本の検査項目・文章・章立ては一切使わない |
| **中身の出どころ** | **Elith の出力だけ**（§3）。見本から文言を持ち込むと §4-1（逐語）違反 |

## 4.4 端末に残す（オフライン）【確定・発注者判断 2026-08-28 / 実装済み 2026-08-30】

**オフラインで見たいのは「AI疾病予防報告書」だけ。アプリ全体のオフライン化は対象外。**
理由 = 他の検査報告書は**紙でユーザーの手元に届く**が、これは**アプリからしか入手できない**。

### 手段 A（正） — 端末のファイルとして残す

`?print=1` の紙面 → 共有 → プリント → PDF →「ファイル」アプリへ保存。
ブラウザのストレージの**外**に出るので、iOS の ITP によるストレージ破棄で消えない。
画面の最下部に手順を出す。主要利用者は 50〜65 代なので、共有シートを自力で辿らせない。
**手順は端末別**（下記・2026-09-02 に作り直し。`?save=1` で開閉していたのは廃止し常時表示）。

**保存された控えは更新も回収もできない。** だから紙面に**作成日と版**を必ず印字する
（実装済み = 表紙の「作成日」「紙面 v1.0」）。消せると誤解させる UI を作らない。

### 端末別の手順【確定・発注者裁定 2026-09-02・案 1＋案 3】

再デプロイ不要）。書式は `端末キー=手順1｜手順2｜手順3` をカンマ区切り。
**上書きすると強調やキーの絵は付かない素の文になる** — 語を直すための口であって、

### 印刷ビュー `?print=1` は `@media print` に依存させない【重要】

iOS には 共有→**プリント**（印刷 CSS が効く）と 共有→**PDF**（効かない・こちらが見つけやすい）の
2 経路がある。後者では**折りたたんだ本文が PDF に載らない＝中身が欠ける**。

→ **`?print=1` は別実装ではなくモード引数**。全展開・UI なしを**通常の画面 CSS で**出し、
`@media print` は上乗せに留める。**どちらの経路でも同じ紙面になる。**
**`?print=1` では折りたたみを使わない。**

- 手順そのものが PDF に載ってしまうので、**保存手順は印刷ビューに置かない**（`verify:screen` が見張る）
- iOS・Android の実機確認は未実施（WebKit は手元で再現できない）

### 紙面の色は印刷でも必ず出す【確定・発注者指示 2026-08-30】

**ブラウザの印刷ダイアログの「背景のグラフィック」は既定がオフ**で、オフのままだと
`background` で塗っている色が全部落ちる。**実測（Chromium `printBackground:false`・同じ
`?print=1` を PDF 化して比較）**では、表紙の淡 teal パネル・円モチーフ・章扉の帯・丸バッジ・
表の teal ヘッダが**白く抜け**、見本 PDF をトレースした紙面が文字と罫線だけになった。

→ **`.report-sheet` に `print-color-adjust: exact`**（`-webkit-` 付きも）。
利用者が何も設定しなくても見本どおりの色で刷れる。**効くのは紙面の中だけ**で、
アプリの他の画面には広げない。

- **数直線（§4.3.6）は特にこれが要る** — 背景色だけで成立する図なので、地色が落ちると
  点も帯も消えて**空白の帯**になる
- 実測（2026-08-30）: 対処前は表紙パネルが `rgb(255,255,255)`（＝色が落ちた）、
  対処後は `rgb(240,250,251)` ＝ `#F0FAFB`（見本どおり）
- **未確認**: 上記は Chromium での実測。**iOS Safari の既定値と、同じ設定項目があるかは
  未確認**（§4.4 の「実機確認は未実施」に含まれる）。iOS の「共有 → PDF」経路は印刷設定を
  通らないので元から色が出るはずだが、これも実機では確かめていない

### やらないこと — **Service Worker で報告書をキャッシュしない**

| # | 理由 |
|---|---|
| 1 | `/report` は **SSR**。キャッシュすると**認証を通さずに HTML を返す**ことになり、端末のロックが解ければ他人の結果が読める |
| 2 | iOS のストレージ破棄の扱いが読めない（Apple 側の変更が続く領域・記憶を根拠にしない = R3） |
| 3 | 実装量が大きい。**報告書 1 点を残すだけなら手段 A で足りる** |

### ただし最小の SW は入れる【実装済み 2026-08-30】

`manifest.webmanifest` が `display: standalone` なので、SW が無いと**ホーム画面起動時に
「アプリの見た目のままブラウザのエラー画面」**が出る。**それを 1 枚の案内に差し替えるためだけ**に置く。

| ファイル | 役割 |
|---|---|
| `public/sw.js` | ナビゲーション要求だけを見る。**必ずネットワークが先**で、失敗したときだけ案内を返す |
| `public/offline.html` | 案内 1 枚。**キャッシュされる唯一のファイル**なので、個人のデータを 1 文字も置かない。CSS もインライン |
| `src/layouts/BaseLayout.astro` | 登録。失敗しても画面は壊さない。`?sw=off` で登録解除できる（実機の逃げ道） |

- **ネットワーク応答をキャッシュに入れない。** 保存するのは `offline.html` だけ
- **ナビゲーション以外は横取りしない**（API・CSS・JS・画像は `respondWith` を呼ばない＝挙動不変）
- **実測（2026-08-30・Playwright）**: 登録 = active ／ キャッシュの中身 = `/offline.html` **1 件のみ** ／
  オフライン遷移 → 案内が出て**検査データの語は 0 件** ／ オンライン復帰 → 本物の紙面が出る
  （キャッシュを返し続けない）／ 非ナビゲーション要求は素通し ／ `?sw=off` で登録数 1 → 0

## 4.10 改ページ・余白・ページ番号【確定・発注者指摘 2026-09-03】

> 印刷した PDF を見て「**改ページ、ヘッダー・フッターの余白が美しくない。ページ番号はあった方が良い**」。

### 何が起きていたか（実測）

印刷 CSS が **カード・表・章を丸ごと `break-inside: avoid`** にしていた。
1 ページに収まらない塊まで「割らない」と宣言したため、入りきらないカードが丸ごと次ページへ送られ、
**手前に巨大な空白**が残っていた。加えて **`@page` の余白指定が無く**、本文が紙の上下端に触れていた。

| | 直す前 | 直した後 |
|---|---|---|
| ページ数 | 32 | **30** |
| 本文領域の平均使用率 | 81.2% | **96.5%** |
| 使用率 50% 未満のページ | **5 枚**（最悪 1.7%） | **0 枚** |
| 上下の余白 | 無し（本文が紙の端に触れる） | 上 16mm / 下 14mm |
| ページ番号 | 無し | **N / M**（表紙を除く全ページ） |

### 直し方

**① 割ってよいものは割る。割ってはいけない最小単位だけを守る。**

- `break-inside: auto` … `.rp-card` / `details` / `table` / `.card`
- `break-inside: avoid` … `.rp-nums` / `.rp-gauge` / `.rp-lrow` / `.rp-wrow` / `.rp-er` / `.rp-axis` / `tr` / `li`
- `break-after: avoid` … 見出し（`.rp-axis` / `.rp-h3` / `h2`〜`h4` / `summary`）
  — 見出しだけがページの最後に残らない（「全編」だけのページが出ていた）
- `thead { display: table-header-group }` … 表が跨いだら teal のヘッダを次ページにも出す
- `p, li { orphans: 2; widows: 2 }`

**② 余白とページ番号は `@page`。**

```css
@page { size: A4; margin: 16mm 0 14mm; }   /* 左右は .rp-inner の 8.1% が持つ */
@page :first { margin-top: 0; }            /* 表紙の teal 帯は紙の端まで（見本 p1） */
@page { @bottom-left {…} @bottom-center { content: counter(page) " / " counter(pages); } @bottom-right {…} }
@page :first { @bottom-left { content: "" } … }   /* 表紙には振らない */
```

- **ページ番号は「捏造」に当たらない。** ブラウザが実際に数えたページ数
  （`counter(page)` / `counter(pages)`）で、当方が推測した数ではない。
  §4.3.2 に「CSS だけでは採番できないので入れない」と書いていたのは**誤り**で、
  [Chrome 131 以降はマージンボックスに generated content と page カウンタを置ける](https://developer.chrome.com/blog/print-margins)。
  実測でも全ページに連番が出た。
- **走りフッターは `@page` の 2 本目に分けて書く。** マージンボックス未対応のブラウザでは
  その塊だけが捨てられ、**余白指定は生き残る**（帯が出ないだけで紙面は崩れない）。
  作成日と版は表紙に印字してあるので、そこが欠けることもない。
- **氏名と作成日は SSR で CSS に埋める**（`report.astro` の `pageCss`）。Astro の通常の
  `<style>` は静的な値しか持てないので `<style is:inline>` で出す。
- 従来の `.rp-sheet-foot`（紙面の最後に 1 回だけ出る帯）は**撤去**した。見本の
  「全ページ下の帯」になっていなかったうえ、番号を振れない。

### 確かめ方 — `npm run verify:print`

`?preview=1&print=1` を**実際に PDF へ焼いて**測る（要 `npm run dev` と poppler-utils）。

1. 表紙にページ番号が無い
