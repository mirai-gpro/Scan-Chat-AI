# AI疾病予防報告書 PDF の作り直し手順

紙面を直したあと、既に配った PDF を**同じ受領 JSON から作り直す**ための手順。
2026-09-28 作成（トランスコスモス 10 名で 3 回続けて「どれが最新か分からない」状態になったのを受けて）。

---

## 0. まず「いま配っている PDF がどの版か」を測る

**ファイル名は当てにならない。** 実例:

| 届いたもの | 実際 |
|---|---|
| `…_20260925.zip` / フォルダ名「再修正版」 / ファイル名「修正版」 | **中身は 2026-09-18 07:24 UTC 生成**（PDF の `CreationDate`） |

```bash
npm run verify:report-batch -- /path/to/報告書.zip      # zip でもフォルダでも可
```

`poppler-utils` が要る（`apt-get install -y poppler-utils` / `brew install poppler`）。
**引数に repo の中を渡すと中止する** — 報告書には氏名が印字されているため。

見ているのは紙面に必ず出る「版の指紋」:

| # | 見るもの | 現行（`fd5e112` 以降） | 古い |
|---|---|---|---|
| ① | 検査値の表の列 | 項目名 / 値 / **検査日** | 項目名 / 値 |
| ② | 章扉の見出し | **AI 疾病予防アドバイス** | AI 診断による疾病予防アドバイス |
| ③ | 出典行 | Elith の節名だけ | 「（要約）」「§1〜§N」「冒頭 2 文」 |
| ④ | 撤去済みの文言 | 0 件 | 「今回の所見」「すぐ受診」「—」 |
| ⑤ | 表紙 | 空ラベル無し | 「作成日」の後ろが空 |

**`判定` `基準値` `要注意` は落とさない。** Elith の地の文に普通に出る
（「AST：基準値 13〜30 U/L」「前述の通り」）ので、**列見出しとしての出現だけを落とし**、
地の文は件数と前後を出すに留める。語が在ることと、その語を当社が見出しに使ってよいことは別。

生成時刻が複数ある場合は「一部だけ作り直した可能性」として警告する。

---

## 1. 作り直しに要るもの

**受領 JSON が要る。PDF からは作り直せない。**

```
<入力ディレクトリ>/            ← **repo の外**に置くこと (氏名が入る)
  <id-1>/
    report_text.json          必須 — Elith の本文 10 セクション + health_age
    health_checkup.json       任意 — 検査値
    meta.json                 任意 — 氏名 / 実年齢 / 作成日 / 第 N 回
  <id-2>/
    ...
```

**PDF のテキストから受領 JSON を復元して作り直してはいけない。**
紙面は逐語なので一見できそうに見えるが、テキスト抽出の改行・ハイフネーション・
文字化けがそのまま新しい紙面に入り込み、**原文改変（捏造）になる**。
出力から入力を起こすのは、スキャンの golden を run の出力から作って
誤りを継承した 2026-08 の失敗と同じ形。

受領 JSON の在処:

- **本番 DB** `diagnosis.diagnosis_results`（`report_text` / `checkup_values`）
- **取り込みに使ったファイル**（Elith からの受領分）

---

## 2. 作り直す

```bash
npm run dev                                   # 別ターミナルで

REPORT_RENDER_DIR=/path/to/入力 \
  node scripts/render-report-pdf.mjs --out /path/to/出力
```

- 紙面は `/report?print=1` の**本番と同じレンダラ**を印刷するだけ
  （別に組むと紙面が 2 系統になる）。`?render=<id>` は `import.meta.env.DEV` で
  囲ってあるので**本番ビルドには出ない**。
- 1 件だけ試すなら `--only <id>`。
- **入力・出力とも repo の外**を指すこと（スクリプトが中止する）。

---

## 3. できたものを測る

```bash
npm run verify:report-batch -- /path/to/出力
```

**全件 ✓ になってから配る。** ここで ✗ が出るなら、dev サーバが古いブランチを
見ているか、`git pull` していない。

## 5. 既知の宿題

- **`758fd5e`（2026-09-18「表紙の作成日も値が無ければラベルごと出さない」）が
  本番ブランチに入っていない。** 本番の `report.astro` は今も無条件で
  `作成日` を印字する。10 名の PDF はこの修正を**含む**状態で作られており、
  **本番からは再現できない**。作り直す前に、この 1 本を本番へ入れるかを決めること。
- 2026-09-18 生成の 10 名のうち **坂田様だけ検査値の表が 5 行**（他は 13〜15 行）。
  本文との矛盾は無かったので受領データ側の差と思われるが、作り直すときに
  受領 JSON と突き合わせて確認する。
