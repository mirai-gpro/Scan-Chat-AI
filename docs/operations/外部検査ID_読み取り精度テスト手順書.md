## 2. プリベント（シール台紙）

### System instructions

```text
あなたは検査キット同梱書面の読み取り役です。画像から次の 2 つだけを読み取ります。

1. `barcode_value` — 書面に印刷された **1次元バーコード**（横線のバーコード）が表す数字列。
2. `printed_id_value` — その近傍に**文字として印字されている「ユーザーID」**の数字列。

厳守:
- **QR コード（正方形の二次元コード）は読まない。** 画像に QR があっても値を返さない。
  QR の内容を `barcode_value` や `printed_id_value` に入れてはいけない。
- 読み取れないものは **null**。推測で数字を作らない。桁を補わない。
- バーコードの下に数字が印字されている場合、それは `barcode_value` として読んでよい。
  **英字で挟まれていることがある**（例: `A` + 数字 + `A`）。その場合は**見えたとおり**に返す。
  英字を落として整えなくてよい（こちらで処理する）。
- **パスワードと URL は読まない。** 書面にはログイン用のパスワード（英字と数字が混ざったもの）と
  URL が印字されているが、どちらも値として返してはいけない。
- 2 つは**別々に報告する**。一方だけ読めたら他方は null にする。
  値が同じでも、それぞれの場所から読んだ結果をそのまま入れる。
- 対象の書面に見えない（別の紙・封筒・空白など）ときは両方 null にし、`note` に理由を 1 文で書く。
```

### User（画像と一緒に送る 1 行）

```text
この書面から 1次元バーコードの数字列と、印字された「ユーザーID」の数字列を読み取ってください。QR コードは無視してください。
```

## 4. JSON Schema（両方で共通）

**QR のフィールドを作らない**のが仕様上の要点（作ると QR の値が候補に混ざる）。

```json
{
  "type": "object",
  "properties": {
    "barcode_value": {
      "type": "string",
      "nullable": true
    },
    "printed_id_value": {
      "type": "string",
      "nullable": true
    },
    "note": {
      "type": "string",
      "nullable": true
    }
  },
  "required": [
    "barcode_value",
    "printed_id_value"
  ]
}
```

## 5. 合格の見方

**モデルの出力をそのまま採点しない。** アプリは必ず後段を通す:

`normalizeExternalId`（全角→半角 / 区切り除去 / **start/stop を 1 文字剥がす**）
→ `passesStructuralGuard`（数字のみ 4〜20 桁）
→ `matchesExpectedPattern`（app_config の `labid.*_pattern`）
→ `evaluateExternalId`（採否）

下の表は**その後段を実際に動かした結果**。期待値を書いたものではない。

期待パターン: プリベント `^704000[0-9]{3}$` / デメカル `^[0-9]{15}$`

| barcode_value | printed_id_value | 採る値 | 判定 | 理由 | |
|---|---|---|---|---|---|
| `A704000123A` | `704000123` | `704000123` | **confirmed** | — | **これが合格形**。start/stop を剥がして一致 |
| `704000123` | `704000123` | `704000123` | **confirmed** | — | デコーダが start/stop を返さない場合も同じ |
| `null` | `704000123` | `704000123` | **review_required** | single_source | バーコードが読めず印字だけ |
| `A704000123A` | `null` | `704000123` | **review_required** | single_source | 印字が読めない |
| `A704000123A` | `704000124` | `704000123` | **review_required** | barcode_ocr_mismatch | **食い違い**（バーコードを採る） |
| `*704000123*` | `704000123` | `704000123` | **review_required** | single_source | Code39 で返ると剥がさない |
| `704000` | `704000` | `704000` | **review_required** | pattern_mismatch | 桁が足りない |
| `202500000000000` | `202500000000000` | `202500000000000` | **confirmed** | — | **これが合格形**（15 桁・両方読めた） |
| `null` | `202500000000000` | `202500000000000` | **review_required** | single_source | 印字だけ |
| `0120100302` | `null` | `0120100302` | **review_required** | single_source, pattern_mismatch | **電話番号を読んだ** |

### 見るべき点（この 4 つ）

1. **`barcode_value` に `A…A` が返るか。** 返ってよい（剥がすのはこちら側）。
   **英字を落として整えてくれなくてよい** — プロンプトでそう指示している。
2. **`printed_id_value` に ID が返るか。** プリベントの合格は `barcode` と `printed` が
   **両方**揃って一致したとき（`confirmed`）。片方だけなら確認待ちになる。
3. **パスワードが返っていないか。** プリベントの台紙にはログイン用のパスワードが印字されている。
   `barcode_value` / `printed_id_value` / `note` の**どこにも**出てはいけない。
4. **QR の中身（URL）が返っていないか。** スキーマに QR の欄は無いが、他の欄へ紛れていないか見る。

### 回数

**同じ 1 枚で 3 回**流す（temperature 0 でも毎回同じとは限らない）。
**3 回とも上の 4 点を満たせば ③ は合格。**
1 回でも外すなら、まず撮り方（影・傾き・寄り）を変えて測り直す。

### 落ちたとき

| 症状 | 次の手 |
|---|---|
| バーコードだけ読めない | `@zxing/library` の同梱を再検討（正本 §6.4 の案2）。**iOS Safari に `BarcodeDetector` が無い**ので、クライアント単独の方式には戻さない |
| 印字だけ読めない | 寄って撮る案内を足す |
| **パスワードが返る** | プロンプトの禁止文を強める。**直すまで on にしない** — 証跡画像は S3 に残るので、資格情報が応答と台帳に流れる |
| 毎回ばらつく | `scan.model` を変えて測り直す（`app_config` の enum にある範囲で） |
