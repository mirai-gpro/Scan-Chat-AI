### 2.3 稼働環境

| 層 | 採用技術 | 備考 |
|---|---|---|
| アプリ実行環境 | Vercel（サーバーレス関数・リージョン `iad1`） | 関数タイムアウト 60 秒 / 定期処理（cron）による非同期処理を併設（スキャン読取＝毎分 / 外部連携データの書き出し＝毎日 23:00 JST / 受領データ取込＝毎日 09:00 JST） |
| データベース | Supabase（PostgreSQL） | 2 スキーマ分割。マイグレーション 28 本 |
| オブジェクトストレージ | AWS S3 | ① 検査原本用（東京リージョン `ap-northeast-1`・保存時暗号化・10 年保管の書込ロック）② 外部連携用 ③ スキャン一時領域（1 日で自動削除） |
| フロントエンド | Astro v5 + TypeScript + Tailwind CSS | サーバーサイドレンダリング |
| 生成 AI（検査票読取・音声対話） | Google Gemini | モデルは管理画面から無停止で切替可 |

> **開発中の仕様改善**: 見積書 (1)② は「AWS アカウント設計、VPC・サブネット・ルーティング・セキュリティグループ設計、IAM 権限設計、RDS/Aurora DB 設計、S3 ストレージ階層設計、本番/ステージング環境分離、バックアップ運用設計」を前提としていた。実装では **Vercel（アプリ実行環境）＋ Supabase（データベース）＋ AWS S3（ストレージ）** の 3 層構成を採用した。ネットワーク分離・権限設計・環境分離（本番／プレビュー）・バックアップ運用・ストレージ階層（原本保管／連携用／一時領域）という設計要求はすべて充足しており、**金額の変更はない**。

当社が実装した外部連携は以下のとおり。**いずれも当社側の入出力処理を規定するものであり、接続先システムの内部仕様は本書の範囲外である。**

| # | 連携先 | 当社側の処理 | 方式 |
|---|---|---|---|

#### 2.4.1 外部 AI 解析システムとの受け渡し仕様（当社側）

**送信データ（当社が書き出す）**

| 項目 | 仕様 |
|---|---|
| 格納パス | `user/{client_id}/date/{YYYY_MM_DD}/` |
| ファイル名 | `{format_id}_date_{YYYY_MM_DD}_user_{client_id}.json` |
| `client_id` | **非個人情報の識別子**（`diagnostic_user_id`）。氏名・住所・生年月日は含めない |
| 形式種別（`format_id`） | `HealthCheckupData` / `BloodTestData` / `GeneticTestResultData` / `CancerRiskAssessmentData` / `LifestyleQuestionnaireData` / `Other`（6 種）＋ 当社算出の `HealthAgeData` |
| 書き出しの起動 | 必要な検査が揃った時点で定期処理（毎日 23:00 JST）が自動実行。管理画面からの手動実行にも対応 |
| 冪等性 | 同一回の二重送信を防止（納品履歴を 3 テーブルで管理。同一内容なら書き込みを行わない） |
| 検証 | **書込後に読み戻して内容一致を確認**。不一致の場合は納品失敗として記録 |

**受信データ（当社が受け付ける）**

| 項目 | 仕様 |
|---|---|
| 形式 | JSON（章立て構造）＋ 組版済み PDF（任意） |
| 当社が処理する章 | `abstract` / `summary` / `blood_analysis` / `diet` / `exercise` / `sleep` / `lifestyle` / `medical_visit` / `nutrients` / `references` / `cancer_screening`（計 11 章） |
| 取込経路 | 管理画面からのアップロード |
| 世代管理 | 新しい版の受領時に旧版を `superseded` 状態へ変更し、常に最新 1 件を表示 |
| 当社の処理 | **受領文の内容を一切変更せず**、要点の選択と段落割りのみを行って表示（第 3 章 3.4 参照） |

### 3.4 報告書生成の仕様（F-12）

#### 3.4.1 表示方式

| 項目 | 仕様 |
|---|---|
| 構成 | **ダイジェスト（要点カード）＋ 全編（折りたたみ）の 2 層** |
| 表紙 | 氏名・作成日・ウェルネス年齢（実年齢との比較数直線） |
| 冒頭 | 受領 JSON の `abstract` を**全文そのまま**表示（見出し・枠を付けない） |
| ダイジェスト | 章ごとに要点カードを表示。カード下端から全編の該当章へ遷移（遷移先の章は自動で開く） |
| 全編 | 受領した全文を章ごとに折りたたんで保持。既定は閉じた状態 |
| 検査値 | **項目名と値の 2 列のみ**。当社は判定・基準値の欄を作らない（受領データに判定フィールドが無いため） |
| 印刷 | 印刷専用ビュー（`?print=1`）。全章展開・操作ボタン非表示・ページ番号（N / M）つき |

#### 3.4.2 可読化処理の内容（当社が行う処理の全て）

**当社は受領文の内容を創作・要約・言い換えしない。** 行う処理は以下の 3 つのみであり、**文字の増減を伴わない**。

| 処理 | 内容 | 文字の増減 |
|---|---|---|
| 要点の選択 | どの文をダイジェストのカードに出すかを選ぶ（選ばれなかった文は全編に保持） | なし |
| 段落割り | 2 文ごとに空行を入れて段落に分ける | なし |
| 主題の強調 | 文頭の主題提示部（「〜について」「〜は」等）を文法的に拾って太字にする | なし（強調記号を挿すのみ） |

**この制約は自動検証で機械的に担保している。** 報告書の紙面に出る全文が受領 JSON の部分文字列であることを検証するスクリプトを CI に組み込んでおり、当社が文言を追加・改変するとビルドが失敗する（第 9 章 9.4 参照）。

実測: 受領本文 20,046 字 → ダイジェスト 1,478 字（削減率 92.6%）、全編は全文保持。
