## 1. データフロー

```
会員がWebアプリでAI問診に回答
  → 回答データ(共通アンケート・設問No 1..81)
     → [本仕様のマッピング] 各社が必要な項目だけ抽出・変換
        → 会社別CSVを生成
           → 各社へ受け渡し(受渡方式は docs/lab/lab_data_reception_overview.md)
```

- **入力**: AI問診の回答（共通アンケート。設問No は Wellfort Forms の採番）。
- **出力**: 会社別 CSV（会社ごとに必要項目・並び・様式が異なる）。
- 変換ロジックはサーバ側（admin/API）に集約。鍵・処理は Vercel 側（CLAUDE.md）。

>   **血液（リージャー）列は本仕様の対象外**（§6 / §7-7）。
> - **デメカル→Wellfort**：**血液検査結果 CSV**（受取・取込。**本仕様の対象外・変更なし**。`elith-blood-csv`／`demecal_attended_manual_guide.md`）。

## 2. 番号体系（重要・混同注意）

- **共通設問No**（本仕様の左端）＝ **AI問診（共通アンケート）の設問番号**（Forms No.）。
- **各社の数値**＝ その会社シートの**行番号**（設問番号ではない。Excel 注記「各検査・AIレポートは設問Noではなく**行数**で表示」）。本仕様では各社の行番号を §4 の項目リストの「行」と対応させる。
- 記号:
  - `×` … その会社では**不要**（CSVに含めない、または空）。
  - `—` … Excel 上 空欄（＝対象外／未使用）。
  - `A,B,C`（カンマ）… 複数行に展開（複数選択・分割入力）。
  - `A～B` / `A~B`（範囲）… 連続行に展開。
  - 複数対応は「1設問→複数項目」または「複数設問→1項目(結合)」の両方があり得る（§5参照）。

## 5. CSV生成ルール（実装）

1. **対象項目の決定**: 会社ごとに §4 の全項目が CSV の対象。うち **§3 で `×`/`—` の共通設問に紐づく項目は問診からは埋めない**。
2. **値の充填（順方向）**: 回答のある共通設問No について、§3 のその会社セルの行番号へ値を書き込む。
   - `カンマ`複数 → 各行へ展開（複数選択はフラグ/該当行に対応）。
   - `範囲(A～B)` → 連続行へ展開。
   - `複数設問→同一行` → 結合（区切りは会社様式に従う）。
3. **記載方法の変換**:
   - `[フリー]` … 回答値をそのまま（数値・テキスト）。単位はプレプリント（§4/シートの単位列）に従い数値のみ入れる等、会社様式に合わせる。
   - `[選択]` … 会社様式の**選択肢コード/表記**へ変換（各社シートの選択肢列 G以降がマスタ。問診の回答値→会社選択肢の対応表を別途保持）。
4. **検体・検査固有項目（★）**: AI問診に無い（ALA日時・採尿日時・整理番号・国籍/人種/出生地 等）。キット同梱情報・工程入力・会員プロフィール等の**別ソースから供給**（実装時に供給元を確定）。
5. **未マッピング/空**: 値が無い項目は会社様式の既定（空欄/「-」）に従う。捏造しない。

## 8. 実装方針（提案）

- **入力**: AI問診回答（`diagnosis` スキーマ／問診結果）。**変換ロジック**: `src/lib/` に会社別 CSV ビルダ（`buildLabCsv(company, answers, mapping)`）、マッピングは本仕様をデータ化した定数表（`共通設問No → 会社別行`）で保持。
- **選択肢変換**は会社別対応表を同梱。**PII 項目**は会社が要求する場合のみ会員プロフィールから取得（Elith 経路には載せない）。
- **出力/受渡**は `docs/lab/lab_data_reception_overview.md` の各社経路に接続。
  （血液=**PowerShell**〈下りのみ・上りは対象外〉／がん=専用ポータル+S3 を提案中／LAiF=S3／遺伝子=下りのみ・方式再検討）
- 生成は admin（サーバ側・鍵は Vercel）。CSV は会社様式に厳密準拠。
